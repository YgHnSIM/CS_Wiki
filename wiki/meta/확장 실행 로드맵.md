## 단계별 범위

### P0 — 기존 핵심 관계 보강

새 문서 없이 [[컴퓨팅 능력의 발달사]], [[평균 성능은 왜 서비스의 컴퓨팅 능력을 설명하지 못하는가]], [[인코딩 심화]], [[비트 패턴과 해석 규칙]], [[Unix와 C]], [[Fortran과 컴파일러]], [[병렬 컴퓨팅은 시간을 줄이는가 문제를 키우는가]], [[범용성은 어떻게 컴퓨팅 능력이 되었는가]]에 출처 기반 핵심 관계를 추가한다.

### P1 — 대기열·SLO·에너지

리틀의 법칙과 예측 가능한 DNN 서빙 원전을 참고 자료로 추가하고, 대기열·부하 제어를 LLM 서비스 지표, 연속 배칭, 꼬리 지연, 에너지 비용에 연결한다.

### P2 — 분산 상태·일관성

CAP, Raft, Spanner 원전을 바탕으로 분산 합의·복제 로그·일관성을 기존 결함 허용·가용성·꼬리 지연 축에 연결한다.

### P3 — 입력 해석·보안

입력 검증과 정수 범위 오류를 유니코드 정규화·동형이의 문자·C 문자열·메모리 안전성·API 경계와 함께 분석한다.

### P4 — 벤치마크 측정 계약

SPEC, LINPACK, Green500, MLPerf, TokenPowerBench의 작업·결과·경계·시간·자원 조건을 공통 비교 틀로 종합한다.

### P5 — 검토·출처 보존

`review` 상태 문서를 원전 대조와 관계 보강 뒤 활성화하고, 공개 접근 가능한 중요 `external-only` 자료의 보존 우선순위를 정리한다.

#### 외부 링크 보존 점검 (2026-07-25)

P1의 전체 링크 검사에서 새 대기열·SLO 자료의 USENIX URL은 정상 응답했고, 기존 NIST 참고 자료 두 건은 직접 PDF 경로 소실로 확인됐다. P5에서 원문·기관 대체 자료를 다시 대조해 [[DLMF Standard Reference Tables on Demand]]는 NIST 출판물 레코드로, [[Handbook of Mathematical Functions with Formulas, Graphs, and Mathematical Tables]]는 현재 응답하는 NIST 공식 편람 기록으로 접근 경로를 갱신한다. `raw/` 원본은 이 점검 때문에 변경하지 않는다.

### B0 — 표현·배치·계약 확장 지도

[[표현·배치·계약은 어떻게 컴퓨팅 능력을 만드는가]]는 다섯 확장의 공통 질문을 유지하며 P6–P10 분석을 한 허브에서 비교한다. P10 통합 검토 뒤 `active/public`으로 승격했고, 색인·개요·학습 경로와 연결했다.

### P6 — 동시성·동기화·메모리 일관성

`ref-092` [[Cooperating Sequential Processes]], `ref-093` [[Monitors: An Operating System Structuring Concept]], `ref-094` [[How to Make a Multiprocessor Computer That Correctly Executes Multiprocess Programs]], `ref-095` [[Linearizability: A Correctness Condition for Concurrent Objects]]를 추가한다. [[동시성]], [[상호 배제와 동기화]], [[순차 일관성]], [[선형화 가능성]]과 「한 프로그램의 순서는 여러 실행 주체에서 어떻게 보존되는가」를 만들고, [[구조적 프로그래밍]], [[운영체제]], [[병렬 확장성]], [[캐시 메모리]], [[복제 로그와 합의]] 사이의 순서·공유 상태·결과 계약을 구분한다.

### P7 — 이기종 컴파일·런타임·성능 이식성

`ref-096` [[LLVM: A Compilation Framework for Lifelong Program Analysis & Transformation]], `ref-097` [[Scalable Parallel Programming with CUDA]], `ref-098` [[Decoupling Algorithms from Schedules for Easy Optimization of Image Processing Pipelines]], `ref-099` [[TVM: An Automated End-to-End Optimizing Compiler for Deep Learning]]을 추가한다. [[중간 표현]], [[이기종 실행 모델]], [[알고리즘과 스케줄 분리]], [[성능 이식성]]과 「한 소스의 의미와 성능은 가속기로 어떻게 번역되는가」를 통해 소스 의미, 스케줄, 런타임, 하드웨어 매핑을 분리한다.

### P8 — 네트워크·RPC·분산 저장

`ref-100` [[Time, Clocks, and the Ordering of Events in a Distributed System]], `ref-101` [[End-to-End Arguments in System Design]], `ref-102` [[Implementing Remote Procedure Calls]], `ref-103` [[The Google File System]], `ref-104` [[Dynamo - Amazon's Highly Available Key-value Store|Dynamo: Amazon's Highly Available Key-value Store]]를 추가한다. [[종단 간 원칙]], [[원격 프로시저 호출]], [[부분 실패]], [[분산 파일 시스템]]과 「로컬 호출과 파일은 원격 상태가 될 때 무엇을 잃는가」를 통해 지연·재시도·멱등성·복제·순서를 연결한다.

### P9 — 자동화 이후의 노동·검증·생산성

`ref-105` [[Expectation vs. Experience: Evaluating the Usability of Code Generation Tools Powered by Large Language Models]], `ref-106` [[The Impact of AI on Developer Productivity: Evidence from GitHub Copilot]], `ref-107` [[Measuring the Impact of Early-2025 AI on Experienced Open-Source Developer Productivity]]을 추가한다. [[자동화 경계]], [[검증 노동]], [[AI 코딩 지원]]과 「자동화는 계산 노동을 없애는가 책임을 옮기는가」를 통해 과제·숙련도·도구 판본·완료 기준·검토 비용을 분리해 기록한다. 서로 다른 실험의 시간 결과를 단일 생산성 배수로 합치지 않는다.

### P10 — 수명 주기 자원 회계

`ref-108` [[GHG Protocol Product Life Cycle Accounting and Reporting Standard]], `ref-109` [[Chasing Carbon: The Elusive Environmental Footprint of Computing]], `ref-110` [[Carbon Emissions and Large Neural Network Training]]을 추가한다. [[수명 주기 평가 경계]], [[운영 탄소와 내재 탄소]], [[전력 사용 효율]]과 「낮은 운영 에너지는 지속 가능한 컴퓨팅을 보장하는가」를 통해 기능 단위, 시스템 경계, 운영 에너지, 시설 오버헤드, 전력 탄소 집약도, 제조 배분량과 장비 수명을 함께 기록한다. 물·광물·공급망 자재는 후속 후보로 남긴다.

### 다음 재개 행동

1. `git status --short`와 `git log -1`로 원자 통합 커밋과 작업 트리 상태를 확인한다.
2. 표의 P0–P10이 모두 `완료`인지, `ref-110`까지의 ID와 세 학습 경로가 유지되는지 확인한다.
3. 이후 확장이 필요하면 `ref-111`부터 새 우선순위를 추가하고, 해당 범위의 참고 자료·개념·분석·관계·학습 경로·색인·로그를 같은 변경 묶음으로 작성한다.
4. 공통 검증과 `git diff --check`를 통과한 뒤 커밋·푸시하고, 이 표와 [[log]]에 새 재개 지점을 기록한다.

## 재개 절차

1. `git log`와 완료 커밋 열로 원격 반영 여부를 확인한다.
2. 공통 검증 결과와 세 학습 경로·`ref-110` 기준을 확인해 통합 범위가 온전한지 검토한다.
3. 후속 확장이라면 새 우선순위를 이 표에 추가하고, 그 범위만 편집한다.
4. 커밋 해시와 검증 결과를 이 표와 [[log]]에 기록한 뒤 푸시한다.
