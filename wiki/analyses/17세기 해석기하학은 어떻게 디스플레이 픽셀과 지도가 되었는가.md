## 분석 틀

17세기 데카르트(René Descartes)와 페르마(Pierre de Fermat)의 해석기하학, 그리고 뉴턴(Isaac Newton)과 라이프니츠(Gottfried Wilhelm Leibniz)의 미적분학은 종이 위의 추상적 수학 이론으로 머물지 않고, 현대 모바일 컴퓨팅 하드웨어와 운영체제의 물리 계층에 문자 그대로 육화(Incarnation)되어 실행되고 있다.

이 분석은 스마트폰이라는 5인치 유리판 장치를 구성하는 세 가지 핵심 서브시스템을 축으로 삼아, 17세기의 기하학적·해석학적 원리가 어떻게 현대 컴퓨터 아키텍처의 연산 파이프라인과 메모리 구조로 변환되었는지를 규명한다.

1. **디스플레이와 GPU**: 데카르트 이산 직교 격자 $(x, y)$가 1차원 선형 VRAM 프레임버퍼 물리 메모리 주소로 사상되는 아키텍처.
2. **터치스크린과 물리 엔진**: 상호 정전용량 격자 무게중심 추적과 뉴턴 점성 감쇠 2계 상미분방정식의 실시간 수치 적분 메커니즘.
3. **위치 인식과 지도 앱**: GPS 위성 삼변측량 비선형 연립방정식의 뉴턴-랩슨 해석과 구면 적분 기반 Web Mercator(EPSG:3857) 등각 투영 파이프라인.

## 기둥 1: GPU와 디스플레이 — 데카르트 격자의 1차원 선형 메모리 사상

스마트폰의 OLED/LCD 화면은 가로 $W$, 세로 $H$개의 물리 서브픽셀로 구성된 2차원 데카르트 직교 평면이다. 그러나 컴퓨터의 물리 메모리(VRAM/DRAM)는 1차원 선형 바이트 어레이로만 주소 지정이 가능하다.

### 2D 격자에서 1D 물리 주소로의 변환 공식

화면 상의 임의의 정수 좌표 $(x, y)$는 비디오 컨트롤러와 GPU 래스터라이저에 의해 다음과 같은 선형 대수 공식으로 물리 메모리 주소로 변환된다:

$$\text{Memory Address} = \text{Base Address} + (y \times \text{Stride} + x) \times \text{BytesPerPixel}$$

여기서 바이트 단위 폭인 $\text{Pitch} = \text{Stride} \times \text{BytesPerPixel}$을 도입하면:

$$\text{Address}(x, y) = \text{Base Address} + y \times \text{Pitch} + x \times \text{BytesPerPixel}$$

- $\text{Base Address}$: 프레임버퍼가 시작되는 VRAM의 기준 주소.
- $\text{BytesPerPixel}$ (BPP): 색상 포맷에 따른 바이트 수 (예: RGBA8888은 4바이트, RGBA16F HDR은 8바이트).
- $\text{Stride}$: 한 픽셀 행(Row)에 할당된 메모리 폭(픽셀 수).

### Stride 패딩과 하드웨어 캐시 라인 정렬

실제 시스템에서 $\text{Stride} \ge W$이며, 행 끝에 패딩 바이트가 추가된다. 이는 DRAM 메모리 컨트롤러의 버스트 길이(Burst Length)와 CPU/GPU 캐시 라인 크기(64바이트 또는 128바이트)에 맞추어 각 주사선의 시작 주소를 정렬(Alignment)하기 위함이다:

$$\text{Pitch} = \lfloor (W \times \text{BytesPerPixel} + A - 1) / A \rfloor \times A \quad (A \in \{64, 128, 256\})$$

만약 행 정렬이 맞지 않으면 하나의 주사선을 읽을 때마다 캐시 라인 분할 접근(Cache Line Split Access)이 발생하여 메모리 대역폭이 낭비되고 스캔아웃 시 화면 찢어짐(Tearing)이나 지연이 유발된다.

### 3D 투영과 피네다(Pineda) 래스터라이저

연속된 3D 기하학을 2D 픽셀 격자로 구워내기 위해 GPU는 $4 \times 4$ 동차 좌표(Homogeneous Coordinates) 행렬을 사용하여 회전·이동·원근 투영을 합성한다. 투영된 2D 삼각형에 대해 피네다의 엣지 함수(Edge Function)를 SIMD/SIMT로 병렬 평가하여 각 픽셀 $(x, y)$가 삼각형 내부인지 판별한다:

$$E_{ij}(\mathbf{p}) = (x - x_i)(y_j - y_i) - (y - y_i)(x_j - x_i) \ge 0$$

또한 TrueType/OpenType 폰트와 벡터 그래픽은 3차 베지에 곡선 $\mathbf{B}(t)$의 1계 도함수(접선 벡터 $\mathbf{B}'(t)$)와 곡률을 실시간 미분 계산하여 서브픽셀 수준의 안티에일리어싱 윤곽선을 생성한다.

## 기둥 2: 터치스크린과 물리 엔진 — 정전용량 격자 추적과 뉴턴 점성 감쇠 미분방정식

사용자의 손가락이 닿는 5인치 유리판 밑면에는 미세한 인듐주석산화물(ITO) 전극 격자가 깔려 있어, 접촉 시 발생하는 상호 정전용량 변화($\Delta C$)를 감지한다.

### 2D 무게중심(Centroid) 추적

터치 컨트롤러 IC는 $120\text{Hz}$ 또는 $240\text{Hz}$의 주기로 센서 노드들을 스캔한 뒤, 전극 간격보다 수십 배 정밀한 좌표를 복원하기 위해 2차원 무게중심 공식을 실행한다:

$$x = \frac{\sum_{i, j} x_i \cdot \Delta C_{i, j}}{\sum_{i, j} \Delta C_{i, j}}, \quad y = \frac{\sum_{i, j} y_j \cdot \Delta C_{i, j}}{\sum_{i, j} \Delta C_{i, j}}$$

### 점성 감쇠(Viscous Damping) 2계 상미분방정식

손가락으로 화면을 튕긴 후 떼는 순간, 모바일 OS(iOS UIKit, Android Choreographer)의 UI 물리 엔진은 뉴턴 역학의 점성 감쇠 2계 상미분방정식을 기동한다:

$$m \frac{d^2 x}{dt^2} + c \frac{dx}{dt} = 0 \implies \ddot{x} + \mu \dot{x} = 0 \quad \left(\mu = \frac{c}{m}\right)$$

이 미분방정식의 해석적 해는 다음과 같은 지수 감쇠 곡선을 이룬다:

$$v(t) = v_0 e^{-\mu t}$$
$$x(t) = x_0 + \frac{v_0}{\mu}(1 - e^{-\mu t})$$

이로써 화면은 허공에서 뚝 끊기지 않고 점성 유체 속을 미끄러지듯 자연스럽게 멈춰 선다. 화면 끝에 도달했을 때의 고무줄 반발은 용수철 복원력이 결합된 **감쇠 조화 진동자(Damped Harmonic Oscillator)** 방정식($m\ddot{x} + c\dot{x} + kx = 0$)의 실시간 수치 시뮬레이션이다.

### 실시간 수치 적분과 8.3ms 프레임 예산

모바일 디스플레이의 $60\text{fps}$($\Delta t \approx 16.67\text{ms}$) 또는 $120\text{fps}$($\Delta t \approx 8.33\text{ms}$) VSYNC 주기에 맞추어, UI 스레드는 매 프레임 수치 적분을 수행한다.

- **명시적 오일러**(Forward Euler)는 조화 진동 시스템에서 에너지를 인위적으로 주입하여 진폭이 폭발하는 치명적 결함이 있다.
- 반면 **반음시적 오일러**(Semi-implicit / Symplectic Euler)는 속도를 먼저 갱신한 후 위치에 반영($v_{n+1} = v_n + a_n \Delta t$, $x_{n+1} = x_n + v_{n+1} \Delta t$)함으로써, 해밀토니안 위상 공간의 면적을 보존하여 무조건적 안정성을 제공한다. iOS와 Android는 최소의 연산량($O(1)$)으로 안정적인 애니메이션을 보장하기 위해 이 신플렉틱 적분기를 표준으로 사용한다.

## 기둥 3: 지도 앱과 GPS — 4원 비선형 연립방정식과 웹 메르카토르 미적분 투영법

스마트폰 지도 앱이 파란색 현재 위치 핀을 꽂기까지의 과정은 20,000km 상공의 우주 위성과 17세기 미적분학의 결합이다.

### 4원 비선형 연립방정식과 뉴턴-랩슨 해법

GPS 위성 4기 이상으로부터 도달한 나노초 단위 신호의 시간 지연에 광속 $c$를 곱한 의사거리(Pseudorange) $\rho_i$는 수신기 3차원 좌표 $(X, Y, Z)$와 수신기 시계 바이어스 $\delta t_r$을 포함하는 비선형 연립방정식을 형성한다:

$$\rho_i = \sqrt{(X - X_i)^2 + (Y - Y_i)^2 + (Z - Z_i)^2} + c \cdot \delta t_r - c \cdot \delta t_{s, i} + I_i + T_i$$

스마트폰의 GNSS 베이스밴드 칩셋은 다변수 자코비안 행렬 $\mathbf{J}$를 구성하고, **뉴턴-랩슨(Newton-Raphson)** 반복법을 고속 수행하여 밀리초 내에 지구중심좌표(ECEF)를 산출한다:

$$\mathbf{x}_{k+1} = \mathbf{x}_k - (\mathbf{J}^T \mathbf{J})^{-1} \mathbf{J}^T \Delta \boldsymbol{\rho}$$

> [!NOTE] 상대성이론의 시간 미분 보정
> 위성의 빠른 속도(특수 상대성이론, $-7.2\ \mu\text{s/day}$)와 약한 중력(일반 상대성이론, $+45.9\ \mu\text{s/day}$)으로 인해 위성 시계는 지상보다 매일 $+38.7\ \mu\text{s}$ 빠르게 흐른다. 이 시간 미분을 보정하지 않으면 매일 약 $11.6\text{km}$의 누적 위치 오차가 발생한다.

### Web Mercator (EPSG:3857)와 시컨트 적분

지구 타원체 좌표(경도 $\lambda$, 위도 $\phi$)를 2차원 평면 지도 타일로 펼치기 위해 모바일 지도 엔진은 Web Mercator 투영 공식을 실행한다:

$$x = R \cdot (\lambda - \lambda_0), \quad y = R \cdot \ln\left(\tan\left(\frac{\pi}{4} + \frac{\phi}{2}\right)\right)$$

이 공식은 국소 사잇각을 완벽히 보존하는 **등각 투영(Conformal Projection)** 조건을 만족하기 위해, 위도에 따라 증가하는 가로 축척 $m_x = \sec \phi$와 세로 축척 $m_y$를 일치시키는 시컨트 정적분으로부터 도출된다:

$$y(\phi) = R \int_0^\phi \sec \theta \, d\theta = R \ln |\sec \phi + \tan \phi| = R \cdot \ln \tan\left(\frac{\pi}{4} + \frac{\phi}{2}\right)$$

남·북위 약 $85.05112878^\circ$에서 $y = \pm \pi R$로 클리핑하여 전세계를 완벽한 $1:1$ 정사각형으로 투영하며, 줌 레벨 $z$에 따라 $2^z \times 2^z$개의 피라미드 타일 격자(Quadkey)로 분할되어 화면 프레임버퍼에 1:1로 앵커링된다.
