## 문제 제기

자동화가 “사람의 일을 대체한다”는 말은 무엇을 일로 세는지에 따라 달라진다. 계산 공장의 작업 분해, Fortran의 자동 번역, 라이브러리·API의 재사용, AI 코딩 지원은 모두 일부 반복 작업의 비용을 낮췄지만, 문제를 정의하고 결과를 확인하며 예외를 처리하고 다른 사람·시스템과 통합하는 일을 자동으로 없애지는 않았다.

따라서 자동화의 효과를 평가할 때는 산출량이나 완료 시간 하나보다 **어떤 작업 단위가 도구로 옮겨졌고, 어떤 판단과 결과 계약이 사람에게 남았는가**를 먼저 물어야 한다.

## 작업의 이동

[[인간 계산자와 계산 공장]]에서 계산은 사람 사이에 배정된 작업표, 전달 규칙, 검산과 예외 처리로 조직됐다. [[The FORTRAN Automatic Coding System]]은 반복적인 기계어 작성과 주소·레지스터 관련 작업 일부를 컴파일러로 옮겼다. 하지만 소스 프로그램의 의미, 목표 기계에서의 성능, 결과의 수치적 타당성은 여전히 사람이 정하고 검토해야 했다.

AI 코딩 지원은 구현 후보를 더 빠르게 만들 수 있지만, 제안이 현재 저장소의 요구·관례·보안·성능·운영 조건에 맞는지 판단하는 작업을 새로 드러낼 수 있다. 이 변화는 고전적인 자동화와 단절된 현상이라기보다, 표현 비용을 낮추는 계층이 올라갈 때 검증·통합 경계가 함께 이동하는 사례다.

| 시대·도구 | 주로 줄이는 작업 | 새로 중요해지거나 남는 작업 |
|---|---|---|
| 계산 조직 | 반복 산술의 개별 수행 | 작업 분해, 전달, 검산, 오류 추적 |
| 컴파일러 | 기계 명령 작성·일부 최적화 | 의미 보존, 디버깅, 성능·정확성 확인 |
| 재사용·API | 재구현과 탐색의 일부 | 인터페이스 이해, 버전·호환성, 조합 |
| AI 코딩 지원 | 초안 작성·검색·반복 구현의 일부 | 요구 해석, 제안 검증, 테스트·리뷰, 저장소 통합 |

## 생산성 수치를 읽는 계약

[[The Impact of AI on Developer Productivity: Evidence from GitHub Copilot]]은 경계가 분명한 JavaScript 구현 과제에서 Copilot 접근 집단이 더 빨리 완료한 결과를 보고한다. 반면 [[Measuring the Impact of Early-2025 AI on Experienced Open-Source Developer Productivity]]은 익숙한 대형 오픈소스 저장소의 실제 이슈에서 초기 2025년 도구 사용이 허용된 과제가 더 오래 걸렸다고 보고한다. 두 결과는 어느 하나가 다른 하나를 무효화하는 모순이 아니라, 작업·개발자·도구·완료 기준이 다른 측정이다.

| 비교 차원 | 독립 구현 과제 실험 | 친숙한 실제 저장소 연구 |
|---|---|---|
| 작업 | JavaScript HTTP 서버 구현 | 버그 수정·기능·리팩터링 이슈 |
| 맥락 | 비교적 경계가 분명한 과제 | 장기 기여자가 아는 대형 저장소 |
| 성공 기준 | 과제 완료 시간 | 사람이 만족할 PR, 테스트·문서·스타일 포함 |
| 해석 | 해당 과제에서의 시간 효과 | 해당 시점·도구·개발자 집단에서의 시간 효과 |

[[Expectation vs. Experience: Evaluating the Usability of Code Generation Tools Powered by Large Language Models]]은 도구 선호, 완료 시간·성공률, 생성 코드의 이해·편집·디버깅이 서로 다른 관찰 대상임을 보인다. [[The SPACE of Developer Productivity]] 역시 개발 성과를 활동량 하나가 아니라 만족·성능·활동·협업·효율·흐름의 여러 차원으로 본다.

## 책임을 옮기는 자동화

자동화가 안전하고 유용한 결과를 만들려면, 생성 단계와 검증 단계를 하나의 성과로 합치지 않아야 한다. 다음 네 가지를 분리하면 “더 빨리 만들었다”는 말의 범위를 명확히 할 수 있다.

1. **표현:** 사람의 의도를 어떤 입력·제약·문맥으로 도구에 전달했는가.
2. **생성:** 도구가 어떤 코드·설계·테스트 후보를 제안했는가.
3. **검증:** 누가 어떤 테스트·리뷰·정적 분석·운영 관찰로 결과 계약을 확인했는가.
4. **귀속:** 실패·보안 문제·유지보수 비용이 생겼을 때 누가 수정·설명·중단을 결정하는가.

이 틀은 AI 코딩 지원이 생산성을 높인다거나 낮춘다는 결론을 미리 정하지 않는다. 대신 어떤 사람이, 어떤 과제를, 어떤 도구와 검증 체계로, 어떤 결과 기준 아래 수행했는지를 남겨 비교 가능한 질문으로 바꾼다.
